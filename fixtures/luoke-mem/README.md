# 给 agent 的场景样例

螺壳记忆（luoke-mem）对 agent 那一路（工具协议版本 1：outbox、A2UI 卡片、基础页）在几种用户处境下**真实**的答复。
都是 `scripts/record_agent_fixtures.py` 在临时目录里造一份假记忆、跑真的 `python3 -m luoke_mem mcp` 录的，不是手写的：
agent 拿它们当样例数据和测试的输入，就是两边之间的接口说明。代码改了 agent 看到的东西，`--check` 就不过，
要重录、提交，并且在 PR 里说清 agent 那边要不要跟着改。

一个请求起一次 `python3 -m luoke_mem --path <假记忆> mcp --clock <时间>`：标准输入一条 JSON-RPC，标准输出是答复。
螺壳起的是同一个命令（清单 `commands.mcp`：`-m luoke_mem --path {memory} mcp`，不带 `--clock`）。假记忆经 luoke_mem 自己的
接口写进去（`record`、`propose`、`conclude`、`state`、`ask`，时间都写死），不连模型。

**本文件也是录的时候生成的**，不要手改；要改说明，改 `scripts/record_agent_fixtures.py`。

## 重录、核对

```bash
python3 scripts/record_agent_fixtures.py            # 重录，写进 fixtures/agent/
python3 scripts/record_agent_fixtures.py --check    # 重录进临时目录和这里比，不一样就列出差别、退出码 1（tests/test_fixtures.py 也跑它）
python3 scripts/record_agent_fixtures.py --only asks --keep   # 只录一个场景，留下假记忆看看
```

## 每个场景里有什么

| 文件 | 请求 |
|---|---|
| `manifest.json` | 配件清单 `packaging/accessory.json`，加上还没发出去的 `capabilities`（见下） |
| `scenario.json` | 这个场景：处境、假记忆怎么造的、时钟、时区、每一步、窗口上应该是什么样 |
| `server-discover.json` | `server/discover` |
| `tools-list.json` | `tools/list`（`annotations.readOnlyHint`；`mem_open` 带 `_meta.ai.luoke/where: mac`） |
| `resources-list.json` | `resources/list` |
| `read-outbox*.json` | `resources/read` `luoke://luoke-mem/outbox`（`outbox` 也认） |
| `read-summary*.json` | `resources/read` `summary` |
| `read-page-<页>*.json` | `resources/read` `page/overview`、`page/guesses`、`page/kept`、`page/people`、`page/sources` |
| `call-<工具>*.json` | `tools/call`：卡片、页上的点按（带 `ai.luoke/user-action`） |

带 `-after…` 的是点完以后再读的。每个文件是 `{"request": …, "reply": …}`：`request` 是 agent 发的那条 JSON-RPC
（`_meta` 里照 agent 带协议版本、`clientInfo`、`clientCapabilities`，点按的再带 `ai.luoke/user-action`），`reply` 是记忆的答复。
JSON 按键排序、缩进两格。

**和线上不一样的地方**（重放时要换回去）：

- `resources/read` 的 `contents[0].text` 在线上是一段 JSON **文字**（`mimeType: application/json`），这里解开成了 JSON 值；
  重放时 `json.dumps` 回去。
- 版本号写成 `$VERSION`：清单的 `version`、`server/discover` 的 `serverInfo.version`，免得每次升版都重录。
- `manifest.json` 是 `packaging/accessory.json` 加上 `capabilities`（`luoke_mem.agent.capabilities()`）：发出去的清单里还没有它，
  因为螺壳本体现在起不了记忆（本体起的工具只有扫描和搜索），清单写了 `transport: "stdio"`，窗口就会一直说记忆没在运行。
  螺壳能起记忆以后，清单再加上，那时这两份一样。
- 别的没换：记忆的编号是数据库里的顺序号，同一个场景里前后对得上（outbox 的 `ask/3` 就是点按时发的 `ask: 3`）；答复里没有路径。
- 时钟停在各步的 `clock`（本机时间，时区 Asia/Shanghai）。卡片、页上的「11月5日」按它写；`created`、`expires` 是不带时区的本机时间
  （工具协议 §3：不带时区的按本机时间）。

## 重放时要知道的

- agent 要问的：`tools/list`、`luoke://luoke-mem/outbox`、`summary`；打开应用页时读 `page/<页>`。
- 会改动东西的（`mem_reply`、`mem_note`、`mem_forget_tool`、`mem_forget_all`，清单 `actions` 里的四个）只认带
  `ai.luoke/user-action` 的调用，没带的答 `isError: true`、`structuredContent.code: "needs_user_action"`。
  `mem_open`、`outbox_ack` 是只读的。
- 卡片上的点按（`mem_reply`）答 `content[0].text` 一句话、`structuredContent.card` 是**更新原卡片**的消息（没有 `createSurface`，
  组件编号带 `end-` 前缀）、`done: true`，记忆已经把这件从 outbox 撤下。改成的内容带密码、验证码、证件号码时答 `isError`、
  `code: "invalid"`，不带 `done`：卡片留着让用户改。问题在别处答过了，答「这条已经变了……」，也是 `done`。
- 页上的点按（`mem_note`、`mem_forget_tool`、`mem_forget_all`）只答一句话，窗口重新读那一页。
  `mem_note` 的「忘掉」和 `mem_forget_tool` 要页上的勾选框「我知道删了找不回来」（上下文 `sure: {"path": "/checks/sure"}`），
  `mem_forget_all` 要输入框里写「清空」（`confirm: {"path": "/fields/clear"}`），不然答 `invalid`、不删。
- 没录的：`mem_open`（在假记忆上也会真的起页面、开浏览器；答「在螺壳记忆里打开了。」，没有卡片）；`outbox_ack`（只答「好。」，
  记忆不记：答了的由 `mem_reply` 关掉，用户放下的那件在记忆里照旧开着，agent 自己记着放下了）。

## 要对齐的

- 「各应用的授权」页没有做：顶层 ADR 0013 以后本机里不再按应用藏敏感内容，记忆没有授权可改了（记忆自己的页面
  也只留着旧接口）。
- 「在螺壳记忆里看」（`mem_open`）还是打开记忆自己的网页，定位到那一条。记忆的页进了主窗口以后，按钮怎么跳到某一页的某一条，
  和 agent 另外商量。
- 每页最多列 15 条（一张卡片最多 200 个组件），多的写「还有 N 条，在整份记忆里看」，下面是「打开整份记忆」。

## `people`：记忆认出的人

用户发出的邮件里写到几个人：同一个地址写过两种叫法，记忆把它们并成一个人；另一个人只出现在一封信里；还有一个人只在每月的写信记录里。用户打开应用页的「人」，忘掉其中一个。

**怎么造的**：邮件助手从用户发出的邮件里记下三条关于别人的事：「同事：王磊（wanglei@corp.example）」「合作方：Wang Lei（同一个地址）」两条各凭两封信（10月28日、11月5日），「上级：Mira」只凭一封；记忆反刍时把同一个地址的两条并成一个人「王磊」（比较确定，他的名字成了常用说法，给语音当热词），Mira 只有一封信，是猜测；邮件助手还记了用户每月写信给谁（mail-contact）：王磊 9、10 月共 15 封，林晓 9、10 月共 5 封；林晓只出现在写信记录里，写过两个月，也算一个人；写给王磊的信的标题里两次提到用户的常用说法「主控」。

**记忆报的**

- 概览（`summary`）：count 1，「记下了 7 条，有 1 条猜测等你确认。」
- outbox：0 件
- `page/overview`：**概览**；记下了 7 条，有 1 条猜测等你确认。；关于你 2 · 常用说法 5；最近记下的（没问你就记下的，不对就在「记下的」里点「不对」）；林晓；常用说法 · 根据你发出的邮件和你在邮件助手里的操作 · 11月5日；Lei Wang；常用说法 · 根据你发出的邮件和你在邮件助手里的操作 · 11月5日；Wang Lei；常用说法 · 根据你发出的邮件和你在邮件助手里的操作 · 11月5日；王磊；常用说法 · 根据你发出的邮件和你在邮件助手里的操作 · 11月5日……
- `page/guesses`：**猜测**；猜测不拿来用；你点「对」，螺壳的工具才会用它。点「不对」，以后不再提。；上级：Mira；关于你 · 依据 1 条 · 11月5日；按钮「对」→ `mem_note`；按钮「不对」→ `mem_note`；按钮「在整份记忆里看依据」→ `mem_open`
- `page/kept`：**记下的**；螺壳的工具会用这些。不对的点「不对」，以后不再提；「忘掉」连它的依据一起删掉，删了找不回来。；CheckBox「我知道删了找不回来」；林晓；常用说法 · 依据 2 条 · 11月5日；按钮「不对」→ `mem_note`；按钮「忘掉」→ `mem_note`；Lei Wang；常用说法 · 依据 6 条 · 11月5日；按钮「不对」→ `mem_note`；按钮「忘掉」→ `mem_note`；Wang Lei……
- `page/sources`：**各应用写的**；忘掉某个应用写的：它的记录、它归纳的、只靠它的记录得出的理解都删掉；你确认过、否定过、改过的留下。删了找不回来。；CheckBox「我知道删了找不回来」；邮件助手：记录 9 条，理解 3 条；按钮「忘掉邮件助手写的」→ `mem_forget_tool`；你说的和记忆归纳的：理解 5 条（在「记下的」里一条条删，或者清空整份记忆）；清空整份记忆：所有应用写的和记忆归纳的都删掉，找不回来。要清空，在下面输入「清空」。；TextField「输入「清空」」；按钮「清空整份记忆」→ `mem_forget_all`

**点了以后**

- `call-mem_person-forget-unsure.json`：「先勾上「我知道删了找不回来」。」（`isError`，`invalid`）
- `call-mem_person-forget.json`：「从记忆里忘掉了林晓。」
