# 工具和 agent 之间的协议（版本 1，2026-10-15）

工具怎么把"要报的事""能做的事"交给 luoke-agent，agent 怎么代用户调用（顶层 ADR 0014：调用工具能力的只有 agent；协议由 luoke-agent 和各工具商定，写进配件清单）。2026-10-15 和 luoke-mail 对过一轮，按它的意见改过；参考实现（§10）做好后，luoke-mail 0.12.0 照它实现，agent 这边对着它的测试环境走通了一遍（读 outbox、卡片校验、没点按被拒、处理模式没开、执行、撤销、再撤得 stale），同日定为**版本 1**：之后只加不改（§9）。

设计的理由见 [DESIGN.md](../DESIGN.md) §3、§4。

## 1. 配件清单里的 `capabilities`

写在工具 .app 的 `Contents/Resources/luoke-accessory.json` 里（luoke-core V1 §8，主控原样保存、经 `GET /accessories` 给 agent）：

```json
"capabilities": {
  "protocol": 1,
  "socket": "~/.luoke-mail/run/agent.sock",
  "reports": [
    {"kind": "new-mail", "title": "新邮件分拣好了", "urgency": "normal"},
    {"kind": "suspicious", "title": "可疑邮件", "urgency": "urgent"},
    {"kind": "digest", "title": "本周订阅精选", "urgency": "low"}
  ],
  "actions": [
    {"name": "mail_apply_plan", "title": "按方案处理邮件（归档、移到垃圾箱、加星标、写草稿）", "writes": true},
    {"name": "mail_undo", "title": "撤销刚才的处理", "writes": true}
  ]
}
```

| 字段 | 意思 |
|---|---|
| `protocol` | 本协议的版本，现在是 1 |
| `transport` | 可选。`"stdio"`：工具不开 socket，由螺壳本体当子进程起，连接向本体要（§2a）；这时不写 `socket`。不写就是开 socket |
| `socket` | 工具在哪个 Unix socket 上提供能力（`~` 开头）。放在工具自己的数据目录里，目录 700：必须在清单 `data` 声明的、和工具编号绑在一起的目录下（`~/.<编号>`、`~/.luoke/<去掉 luoke- 的部分>`、`~/Library/Application Support/<编号>`）；不在的（含经软链接指到外面的），agent 不接。每次连之前 agent 再查一次：路径本身要是 socket（不是软链接）、只有一个硬链接、真实路径还在那个目录下，不过就当没在运行 |
| `reports` | 能报哪几类事：`kind`（工具内唯一的短键）、`title`（给用户看的名字，设置页里"每类事怎么告诉你"用）、`urgency`（默认急不急：`urgent` / `normal` / `low`，每件事还可以自己带，但不能比这里写的急；清单里没有的那一类最多 `normal`） |
| `actions` | 能做哪几件会改动东西的事：`name`（MCP 工具名）、`title`（给用户看）、`writes: true`。安装和设置里给用户看"它能让 agent 代你做什么"。只读的不用列 |

这份是静态的、给人看的；参数、卡片从运行中的工具拿（下面）。

**编号**（清单的 `accessory`）：小写字母、数字和 `.`、`_`、`-`。agent 自己用的不能用：`memory`、`agent`、`luoke-agent`、`luoke-core`、`luoke`、`hub`、`notifications`，以及 `luoke-core` 开头的（`luoke-core-dev`、`luoke-core-lab` 这些）。主控列出了两个同样编号的，agent 两个都不接。

## 1a. 基础页和权限：`service`、`permissions`、`listing`（2026-10-27 加，luoke-agent#3，顶层 ADR 0014 的 10-27 修订）

只加不改，不升版本（§9）。三块都可以不写，不写的工具照样只出卡片。窗口由螺壳.app 画，agent 供内容；字段由 luoke-agent 和 luoke-core 商定，luoke-audit 先实现（luoke-audit#34）。界面上叫「应用」，协议里照旧叫「工具」。

```jsonc
"service": {
  "summary": true,
  "pages": [{"id": "overview", "title": "概览"}, {"id": "cleaned", "title": "清理记录"}],
  "ui": {"open": "audit_open", "pages": [{"id": "details", "title": "全部明细"}]}
},
"permissions": [
  {"id": "fda", "kind": "system", "owner": "luoke", "tcc": "SystemPolicyAllFiles", "title": "完全磁盘访问",
   "facts": ["看文件名、大小、修改时间", "结果不出这台 Mac"], "without": "degrade"},
  // 不在螺壳.app 里的工具才这样写
  {"id": "calendar", "kind": "system", "tcc": "Calendar", "title": "读写日历", "request": "<工具的申请动作>"},
  {"id": "mailbox", "kind": "account", "title": "邮箱", "page": "accounts", "remove": "mail_disconnect"},
  {"id": "auto", "kind": "delegate", "title": "不用点就清 4 类", "on": "audit_autoclean"},
  {"id": "admin", "kind": "each-time", "title": "删除系统目录里的东西（要 Mac 的密码）"}
],
"listing": {"tagline": "一句话介绍", "category": "系统"}
```

**资源**：`resources/read` 的 `uri` 直接写相对 id，不带 scheme、不带工具名（每个工具一条 socket，问的是谁本来就清楚）。资源地址只在协议里当标识，agent 从不交给系统打开。outbox 在版本 1 里照旧是 `luoke://<工具>/outbox`，工具也可以同时认 `outbox`。

| 资源 | `contents[0].text` | 用在哪 |
|---|---|---|
| `summary`（`service.summary: true` 才有） | `{"count": 3, "text": "一句话"}`；`count` 只算要用户处理的 | 应用页的概览、侧栏的计数。不弹通知，不进简报 |
| `page/<id>`（`service.pages` 里的每一页） | 一组 A2UI v0.9.1 消息，目录 `ai.luoke/a2ui/agent/1`，`surfaceId` 就是页 id；和卡片一样校验、一样的上限（§4） | 应用页里的基础页。页上的按钮照 §5，会改动东西的要用户点、带 `ai.luoke/user-action`。不进 outbox，不进简报 |
| `permissions`（有 `permissions` 才有） | `{"<权限 id>": "granted" / "denied" / "ask" / "on" / "off"}` | 权限页、申请弹窗。工具照实报，agent 不猜、不缓存成"已授权" |

**深页**（`service.ui`）：只写页 id。`open` 是工具的一个**只读**动作，参数 `{"page": "<id>"}`，不带 page 打开首页；由工具自己打开（§5「打开工具自己的页面」），`tools/list` 里带 `_meta: {"ai.luoke/where": "mac"}`。不用自定义 URL scheme。

**权限的四种**：

| `kind` | 怎么拿到 | 怎么收回 |
|---|---|---|
| `system` | 系统权限是螺壳的：写 `owner: "luoke"`。用户点了，窗口交给本体（螺壳.app 的 Swift 部分），本体在自己的窗口里问用户，再去问 macOS。工具不自己问 macOS，也不写 `request`。`request` 只留给不在螺壳.app 里的工具：有系统弹窗的（日历、通讯录、照片）写 `request`，一个写入动作，列进 `actions`；agent 先说明，用户点「继续」，agent 调 `request`，由工具自己的程序发起请求，再读 `permissions`，开了就继续。这种工具没有弹窗的（完全磁盘访问）不写 `request`：agent 照 `tcc` 键打开系统设置对应那一页。`tcc` 键到系统设置页的对照表在 agent 里，只认登记过的几个，不认工具给的网址 | 权限页带用户去系统设置；agent 不碰系统的授权数据库 |
| `account` | 卡片上只给「去设置」：调 `service.ui.open`，带 `page`（要是 `service.ui.pages` 里有的）。凭证只在工具自己的界面里填、存进钥匙串，不进卡片（§8） | 「移除」调 `remove`：写入动作，列进 `actions`，要用户点 |
| `delegate` | 开关由窗口画。开和关是同一个写入动作 `on`，参数 `{"on": true/false}`，列进 `actions`，要用户点。清单里不写默认值，当前值由工具在 `permissions` 里照实报 | 同一个开关。用户放回或撤销过的，工具自己关掉，并在 §8a 的 `auto-done` 里写明；agent 把撤销交给记忆当反证 |
| `each-time` | 不授权，只列出来，告诉用户哪些事永远要点；不画开关 | — |

- `title`、`facts`、`without`（`degrade`：没有这项也能用，只是少做一些）是工具自己说的话，agent 照原文显示，不替工具担保。
- **用到才要**：工具第一次要用到某项权限时，在 outbox 报一件 `kind: "needs-access"`、带 `"permission": "<id>"` 的事，默认 `low`，由 agent 来说；不在安装时一口气全要。系统授权框只在用户答应了之后弹。要的是 `owner: "luoke"` 的那一项时，卡片上要权限的按钮写成主按钮（`primary`）；只有一个工具按钮时不写也行。这个按钮点了不转给工具，由窗口交给本体（界面接口 §3、§10）；卡片上别的按钮照 §5。
- **收回也算数**：用户在系统设置里关掉了，工具下次报的状态里就改过来；agent 在「今天」说一次少做了什么。
- **螺壳自己的权限**（`owner: "luoke"`）用同样的形状登记，状态由本体报（界面接口 §10 的 `POST /host`），工具不用报。工具用不用这一项，用户在权限页上按应用开关（「允许」）。这是用户和螺壳的约定：系统授权给的是螺壳，系统不会替螺壳拦住某一个工具。

**`listing`**：只有 `tagline`、`category`。还没装的应用本机读不到清单，所以由发布流水线（luoke-core `tools/release.py`）把 `listing` 和权限说明（`id`、`kind`、`title`、`facts`、`without`）抄进发布清单，「添加应用」读发布清单。大小、能在哪一档用不由工具报。

授权框只紧跟用户的操作（2026-11-06）：后台不问，工具也不许做会让系统弹框的事。缺了就报 `needs-access`，用户点了才问。

## 1b. 问螺壳：`service.ask`（草案，2026-10-28，luoke-agent#3；和 luoke-core、luoke-audit、luoke-search 商定，实现在窗口合并之后）

```jsonc
"service": {
  "ask": {"suggest": "<工具的只读动作>", "search": "<工具的只读动作>"}
}
```

两个都是只读动作，名字要在 `tools/list` 里、`readOnlyHint: true`。都只在用户点开问螺壳、或打字问的时候才调，不进 outbox，不进简报。

**suggest**（跟着二期的问螺壳）：参数 `{"page": "<页 id 或 \"today\">", "selection": …}`，`selection` 是用户悬停或选中的东西，当数据。回至多 3 条，每条一句话加一张卡片（A2UI，校验和上限照 §4）。

**search**：
- 参数各工具一样：`query`，可选 `since`、`until`（ISO 8601）、`limit`；只带时间、不带字也合法。`query` 原样转给工具，不经模型改写。
- agent 对每个登记了的工具各问一次，10 秒没答的当没有；先回先画，不等齐。只列结果，不用模型写总结（评测过了再说）；按来源分段，顶上「最相关」放各来源 `strong` 的前两条，各工具的分数不混排。
- 各工具只回自己的数据，agent 不跨工具去重（邮件只由邮件助手回）。
- 答复的 `structuredContent`：

```json
{"hits": [{
   "id": "12#p3", "source": "files", "kind": "pdf",
   "title": "租房合同.pdf", "line": "第 3 页", "date": "2026-10-03",
   "snippet": "…押金两个月…", "strong": true, "thumb": "thumb/12", "alt": "合同第一页",
   "actions": [
     {"name": "search_open", "title": "打开", "args": {"id": "12#p3"}, "primary": true},
     {"name": "search_similar", "title": "找相似的", "args": {"id": "12#p3"}}
   ]}],
 "card": []}
```

  - `source` 是工具里的分区，窗口的筛选按钮用它；`line` 是第几页、第几分钟这类一行字；`strong` 表示很有把握。`card` 是后备：只有一个来源、或窗口还没合并时用。
  - 文字（`title`、`line`、`snippet`、`alt`）一律当数据，画成纯文本，不认链接。
  - 每条的 `actions[].name` 必须在这个工具的 `tools/list` 里，不在的不画；按钮只转给出这条结果的工具，`args` 只认结果里给的值。点按照 §5 带 `ai.luoke/user-action`；只读动作的新结果画在原地。会在 Mac 上打开东西的动作照 §5「打开东西的动作」。
  - 日志不记搜了什么、命中了什么。
- **画在哪**：hits 是固定形状的数据，不是 A2UI，所以不进组件目录，卡片里不能引用。LuokeA2UI 里加一个只给窗口用的列表视图（`HitsList`），管每一条怎么画；分段、滚动、加载中、超时、空结果由窗口（luoke-core）管。按钮点了以后，窗口交给 agent，agent 转给工具；窗口不直接找工具。

**Image 组件**（加进目录 `ai.luoke/a2ui/agent/1`，只加不改；hits 的 `thumb` 也照这些规矩）：
- 图只认同一个工具的资源 `thumb/<id>`，不认网址；由 agent 向工具 `resources/read`（`blob`，base64），交给窗口。
- 只认 JPEG、PNG，看文件头认，不看扩展名和 MIME；一张不超过 256 KB；解码前先读像素尺寸，长边超过 2048 就显示占位框。动图只画第一帧，不认 SVG。读不到、超了都显示占位框。
- 图只放在内存里，窗口关了就丢，不写磁盘缓存；手机上的经 Mac 中转，也不留缓存。
- 显示多大由布局定，卡片最多给比例（方或宽）。
- 要有替代文字（`alt`），当数据、画成纯文本，给读屏用；没有就用 `title`。

## 2. 连接

- **传输**：HTTP/1.1，跑在上面那个 Unix socket 上；agent 每个请求 `POST /mcp`，请求体是一条 JSON-RPC 2.0 消息，答复体是一条 JSON-RPC 答复（`Content-Type: application/json`）。只有可选的订阅（§6）用 SSE。
- **消息**：MCP 2026-07-28 版数据层的一个子集。无状态：每个请求的 `params._meta` 带 `io.modelcontextprotocol/protocolVersion: "2026-07-28"`、`io.modelcontextprotocol/clientInfo: {"name": "luoke-agent", "version": "…"}`、`io.modelcontextprotocol/clientCapabilities: {}`（agent 不提供采样、不接 elicitation）。
- **工具要实现的方法**：`server/discover`、`resources/read`（读 outbox）、`tools/list`、`tools/call`。可选：`subscriptions/listen`（§6）。
- **谁能连**：socket 文件的权限只让本账户进。工具不需要令牌。以后再加按代码签名核对调用方（和主控一起做）。
- **工具没在运行**：socket 文件不存在、连不上、读 outbox 或列工具 10 秒不答，agent 都当"这个工具现在没在运行"，不算出错，也不重试到底；下一轮再看。工具退出时删掉 socket 文件；同一个数据目录只有一个进程开它（例如邮件助手持有实例锁的那个）。
- **工具只用标准库也做得到**：这个子集就是几种 JSON-RPC 请求，不需要 MCP 的 SDK。agent 这边会写一个只用标准库的参考实现和一个假工具，工具可以拿去对着测。

## 2a. 由螺壳本体起的工具（`transport: "stdio"`，2026-11-05 加；先从 luoke-scan 的 Go 版做）

有的工具收进了螺壳.app（`Contents/Helpers`），不常驻、不开 socket：螺壳本体当子进程起它，权限算在螺壳名下；agent 不自己起它，只能在本体给的连接上说本协议。

- **连接从哪来**：本体起 agent 核心时给一条私有通道（界面接口 §15）。agent 要连这个工具，就在通道上要一条；本体核对过以后起一次工具，把连到工具标准输入输出的那一端交给 agent。
- **每个请求一条连接**，同 §2：agent 写一行 JSON-RPC 请求，关掉写的一头；工具答一行，读到结尾就退出。中途的通知（没有 `id` 的消息）agent 跳过。不需要 HTTP 和 `POST /mcp`。
- **方法、消息**同 §2。一条消息最多 1 MB。
- **工具没在运行**：本体给不了（没带、用户没开、本体不在）、工具没答就退了、超时，agent 都当这一次没在运行，同 §2。
- **开发和测试**：没有本体时，`serve --dev --tool 配件=exec:程序 参数…` 让核心自己起（每个请求一次）。

## 3. 要报的事：outbox

工具提供资源 `luoke://<配件标识>/outbox`（例如 `luoke://luoke-mail/outbox`），`resources/read` 返回 `contents[0].text` 是下面这个 JSON（`mimeType: application/json`）：

```json
{
  "items": [
    {
      "id": "new-mail/2026-10-15T09:02/me@example.com",
      "kind": "new-mail",
      "urgency": "normal",
      "deadline": null,
      "expires": null,
      "created": "2026-10-15T09:02:11+08:00",
      "why_now": "今早到了 5 封要你处理的",
      "title": "5 封新邮件要处理",
      "summary": "王老师问答辩时间（周五前回）；房东发来续租合同；另外 3 封是通知，打算归档。",
      "card": [ /* A2UI 消息，见 §4 */ ]
    }
  ]
}
```

- **它是一份状态，不是一串消息**：列的是"现在还想告诉用户的事"。agent 读到新编号就收进来，读不到了（工具撤下了）就撤掉对应的卡片。agent 重启、工具重启都不丢。
- `id`：工具内唯一、稳定；内容变了（又来了两封）可以换新编号，也可以同一个编号、换卡片。
- `urgency`：`urgent` / `normal` / `low`；不填用清单里这类的默认值；比它急的按它算。
- `deadline`：事情本身的期限（例如"要在这天前回信"），没有就 `null`。agent 用它排序、决定急不急；过了也照样说，标出"已过期"。
- `expires`：过了这个时间就不必再说了（例如一个限时的提醒），没有就 `null`。过了 agent 撤掉这件。
- 时间都是 ISO 8601；不带时区的按本机时间。
- `why_now`：一句话，卡片上显示"为什么现在问"。
- `title`、`summary`：**纯文本、必填**。通知、卡片画不了时、手机的不带内容的提醒之外的地方都用它们。
- 不放凭证（密码、验证码、密钥、令牌、完整卡号和证件号），和写记忆时的规矩一样（顶层 ADR 0013 第 3 条）。
- agent 每分钟读一次；工具也可以支持订阅，有变化时让 agent 马上读（§6）。

**agent 告诉工具这件事说过了**：调工具 `outbox_ack`（只读的记账，工具可以不实现）：

```json
{"name": "outbox_ack", "arguments": {"id": "new-mail/…", "state": "shown" | "answered" | "dismissed"}}
```

agent 什么时候回：`shown` 在这件第一次说给用户时回一次（进了一份简报、急事的通知，或者窗口开着时它进来、用户看得到），同一个编号不再回；`answered`、`dismissed` 在用户点完、工具答复 `done` 或用户放下时回。用户一直不在、简报没发出去，就不回 `shown`。§8a 的 `auto-done` 被下一轮取代时，工具看有没有 `shown` 决定要不要把上一轮的带进去（2026-10-28 应 luoke-audit 加，luoke-agent#2）。

工具可以据此决定要不要撤下这件事、自己还要不要发通知（见 §7）。邮件助手的做法：`answered`、`dismissed` 撤下这件；`shown` 只记下 agent 说过了，不再为它发自己的通知。

## 4. 卡片：A2UI

- 格式照 A2UI v0.9.1（消息里的 `version` 写 `"v0.9"`）：`createSurface`、`updateComponents`、`updateDataModel`、`deleteSurface`。一张卡片是一个 surface；`card` 是按顺序的一组消息，第一条是 `createSurface`。
- `catalogId` 写 `ai.luoke/a2ui/agent/1`。组件只能是：`Text`、`Row`、`Column`、`List`、`Card`、`Divider`、`Button`、`CheckBox`、`ChoicePicker`、`TextField`、`DateTimeInput`、`Icon`、`ProgressBar`（`value` 0 到 1，只画进度）。不在里面的，整张卡片不画，退回纯文本的标题和摘要。
- 上限：每张 200 个组件，每段文字 2000 字。`Text` 只按纯文本画。
- `Button` 写 `"variant": "switch"` 和 `"on": true` 或 `false` 时画成开关。点了还是这个按钮的动作，开没开听工具重画的页面。`on` 不是布尔值时，还是画成按钮。开关不画按钮的文字，文字只给读屏，它管什么要在旁边另写一个 `Text`。`agent.open_url` 不能这样写。开关和 `ProgressBar` 用在应用页上，「今天」的紧凑表、一件件处理不照它们画。
- `surfaceId` 工具自己起，agent 加上 `<配件标识>/` 前缀；工具只能改自己的卡片。
- **Python 工具可以用帮手**：`luoke_agent/cards.py`（只用标准库，拷进工具自己的仓库用）拼常见的几种卡片：标题和说明、一组每项可选处理的 `ChoicePicker`、一排按钮、执行结果加 [撤销]。Swift 写的工具照格式自己写，或用 `LuokeA2UICore`。
- 一张卡片里列多少项由工具定；邮件助手的"新邮件"最多 8 封各带选项，其余打算归档、移到垃圾箱的合成一行（一个 `ChoicePicker`：照建议 / 先不动），这样排画得了。

## 5. 能做的事：工具调用

- `tools/list` 列出工具的全部 MCP 工具，每个带 `inputSchema` 和 `annotations.readOnlyHint`。会改动东西的必须 `readOnlyHint: false`，并且名字在清单的 `actions` 里。
- **按钮怎么变成调用**：A2UI 按钮的 `event.name` 就是同一个工具的 MCP 工具名，`event.context`（agent 按当时的数据模型把路径换成值）就是 `arguments`。agent 只把按钮转给画这张卡片的那个工具。
- **会改动东西的调用只来自用户的点按**：agent 只在用户亲手点了按钮时调 `readOnlyHint: false` 的工具，并在 `_meta` 里带上

  ```json
  "ai.luoke/user-action": {"surfaceId": "plan-42", "componentId": "ok", "at": "2026-10-15T09:05:40+08:00"}
  ```

  `surfaceId` 是工具自己起的那个（不带 agent 加的前缀），工具可以用它更新这张卡片（例如撤销后的结果）。工具收到会改动东西的调用而没有这一项，就拒绝（防的是 agent 自己的毛病，例如以后对话里的模型想直接调；挡不住本账户里别的程序冒充，见 DESIGN「已知的限制」）。
- **方案**：会改动东西的工具只执行自己出过的方案：参数里带工具给的方案编号，用户能改的只是方案里给出的选项（上例的 `choices` 只能取卡片上列的值）。方案要存在工具自己的库里、重启也在：用户可能隔几个小时才点。工具核对方案还在、选项合法，再看一遍现状（处理模式开着、邮件还在原处），然后执行；结果只说实际做成的。
- **慢的调用**：会改动东西的调用 agent 最多等 5 分钟（例如执行方案时要先用模型写草稿），期间卡片显示"正在处理…"；只读的调用等 30 秒。工具在这之内答复就行，不用另起"进行中"的答复。
- **agent 自己处理的动作**：按钮的 `event.name` 以 `agent.` 开头的不转给工具，由 agent 自己做（工具的 MCP 工具名不能以 `agent.` 开头）：
  - `agent.open_url`，上下文 `{"url": "https://…"}`：只认写死的 https 地址：不带反斜杠、空白和控制字符、userinfo（`@`），主机不空、里面没有 `%`、`[`、`]`，看着像数字的只认规范的 IPv4。按钮的子组件必须是写死文字的 `Text`。agent 交给界面时在按钮上写 `site`（主机名转成 punycode，不是 443 的端口带上；工具自己写的去掉），界面把它画在按钮外面；用户点了，agent 照同一次解析重新拼出网址，用系统浏览器打开。邮件助手的"加入日程"用它。
  - `agent.dismiss`：用户放下这件事（agent 记下，并对工具调 `outbox_ack` 的 `dismissed`）。
- **答复**：`tools/call` 的结果里

  ```json
  {"resultType": "complete",
   "content": [{"type": "text", "text": "已归档 1 封，草稿已放进草稿箱。"}],
   "structuredContent": {"card": [ /* 更新这张卡片的 A2UI 消息，例如换成结果和 [撤销] 按钮 */ ], "done": true}}
  ```

  `content` 的文字必填（纯文本，一句人话，和工具自己页面上的反馈一样）。`done: true` 表示这件事办完了，agent 不再提它；工具同时从 outbox 撤下它。
- **出错**：照 MCP 返回 `isError: true` 和一句给用户看的话；`structuredContent.code` 可以是 `not_ready`（工具还在启动、模型在忙）、`needs_setup`（例如处理模式没开）、`stale`（邮件已经不在原处）、`failed`。不要把技术细节放进给用户看的话。`needs_setup` 时 `structuredContent.card` 可以换成带"打开设置"按钮的卡片（一个只读的工具，打开工具自己的页面）；agent 不替用户去开会改动东西的开关。建议换上的卡片保留原来的方案、加一句说明和那个按钮（`cards.plan_card(..., update=True, note=…, extra_buttons=[…])`，不动数据模型），用户开好设置回来，改过的选项还在，直接再点。
- **撤销**：结果卡片里的 [撤销] 也是一个会改动东西的按钮，走同样的路。
- **打开工具自己的页面**（例如"在邮件助手里看"）：工具自己处理（它最清楚怎么打开到那一封），是只读的。
- **不是从卡片发起的调用**（2026-10-20 应 luoke-search 加，草案）：用户在对话里问、agent 调只读的工具（例如 `search_query`），没有"这张卡片"可更新。这时 `structuredContent.card` 的第一条是 `createSurface`，就是**一张新卡片**，surfaceId 由工具起（每次调用不同）；agent 把它放进对话，之后卡片上的按钮照上面的规矩转回这个工具。这张卡片不进 outbox、不进简报。
- **打开东西的动作**（打开文件、在访达中显示、打开工具自己的页面）：一律带 `_meta: {"ai.luoke/where": "mac"}`，agent 只在用户点了按钮时才调（模型不调，DESIGN §6），不管它是不是只读。`readOnlyHint` 由工具照实写：只打开自己窗口、只在访达里显示的算只读；能打开任意文件、可能让别的程序联网的（例如 `search_open`）建议做成写入，列进 `actions`，没有 `ai.luoke/user-action` 就拒绝。
- **只在 Mac 上有意义的工具**：在 `tools/list` 里给这个工具加 `_meta: {"ai.luoke/where": "mac"}`（例如在 Mac 上打开文件）；用户在手机上时，agent 不调它，卡片上对应的按钮显示成灰的并写明"在 Mac 上"。

## 6. 可选：订阅

工具支持的话，`server/discover` 的 `capabilities` 里声明 `resources`（带订阅），agent 用 MCP 2026-07-28 的 `subscriptions/listen` 开一条长连接，outbox 变了工具发一条通知，agent 马上读。没有订阅也行：agent 每分钟读一次，急事最多晚一分钟。最小版先不做。

## 7. 工具的通知

顶层 ADR 0014：只有 agent 主动找用户，agent 做好以后，各工具不再自己弹系统通知（页面里的提示照留）。但用户可能没装 agent、agent 可能停了。建议：**最近 10 分钟里 agent 读过 outbox，工具就不发自己的通知；否则照旧发**。具体怎么做由各工具定。

## 8. 数据和安全

- 数据不出用户自己的设备（顶层 ADR 0013）。在本机里 agent 可以把 outbox 和卡片的内容、点按后的结果存下来（重启后撤销还在），日志只记元数据（日志可能随诊断导出）。
- 工具不把凭证（密码、验证码、密钥、令牌、完整卡号和证件号）放进 outbox、卡片和答复。
- 链接：卡片里没有可点的链接文字；要打开网页用按钮，界面在按钮外面写明去哪个网站（§5），用户点了再开（防钓鱼）。

## 8a. 工具自己做了的事（顶层 ADR 0016；2026-10-19 和 luoke-mail 商定；agent 和体检在同一个 v1.x 走通，邮件助手公开发布以后实现）

用户确认过的、能撤回的处理习惯（例如"以后某商城的促销都归档"），由工具自动做，每次都要告诉用户、能撤销。邮件助手这样的首发组件公开前冻结（顶层 ADR 0017），公开发布以后实现；体检和 agent、螺壳窗口进同一个 v1.x，这一版走通（ADR 0017 的 11-01 修订）。

**`kind: "auto-done"`**（`urgency: "normal"`）：工具自动做完一批，报成 outbox 里的一件事。

- **一次合成一件**：一次同步里按好几条习惯做的，合成一件报，标题写总数，例如"已按你的习惯处理 9 封"；摘要说按了哪几条习惯。
- **卡片按习惯分组**：每组一行说明（按哪条习惯、动作是什么、几封），列出这几封，每组一个 [撤销]。动作的文字由工具给（"已归档""已加标签「购物」"……），agent 不认动作的种类，`kind` 里也不写死是哪种动作。
- **撤销**：[撤销] 是会改动东西的调用，照 §5 走点按（带 `ai.luoke/user-action`）。每组对应工具的一条操作记录，撤销就撤这一条；工具名和参数由工具定（luoke-mail：`mail_undo` {`execution_id`}）。撤完工具把卡片换成结果；用户撤销由工具记下，交给记忆当这条习惯的反证。
- **撤不回的**（2026-10-21 应 luoke-audit 加；例如清掉会重建的缓存，ADR 0016 修订允许确认一次后自动做）：卡片不给 [撤销]，给 [以后别自动做]，调工具收回那次同意的工具（会改动东西，照 §5 走点按）；摘要写清做了多少、有什么后果（"用到时会重新下载"）。
- agent 照普通事项合并进简报，不当场说。

**`kind: "daily-review"`**（`urgency: "low"`）：每天的复查（ADR 0016 第 4 条）。工具在固定时刻（luoke-mail：每天 20:00）列出当天它处理过的全部和各自的结果。

- 摘要一句话，例如"今天处理了 12 封：归档 8、加标签 2、等你 2"；卡片给这句话和一个打开工具自己页面的按钮（只打开、不改动东西的调用，不要求 `ai.luoke/user-action`）。
- 带 `expires`（到第二天同一时刻），不让旧的复查堆起来。
- agent 照不急的事处理：只有不急的事时一天最多一份简报，或用户打开窗口时看到。
- agent 不在（没装、没运行、没连上工具）时，照旧由工具自己发通知（§7）。

## 9. 版本

- 现在是协议版本 1（2026-10-15），只加不改：可以加字段、加可选的方法、加组件；改含义、改名字、删东西要升版本。
- MCP 跟着 2026-07-28 版；以后 MCP 升版时，由 agent 这边兼容旧的，工具不用跟着改。
- A2UI 锁在 v0.9.1。

## 10. 参考实现

都在本仓库的 `luoke_agent/` 里，只用标准库（Python 3.9 起）：

- `mcp.py`：这个子集的服务端（HTTP/1.1 跑在 Unix socket 上，JSON-RPC 分派，会改动东西的调用没有 `ai.luoke/user-action` 就拒绝）和客户端（agent 用的）。工具可以拷服务端那部分去用，也可以照着自己写。
- `cards.py`：拼卡片的帮手，见 §4。
- `a2ui.py`：按组件目录校验一组 A2UI 消息（组件在不在目录里、`root`、`children` 引用、环、路径绑定、上限）。agent 收到卡片先过它；工具的测试也可以用它查自己出的卡片。
- `fake_tool.py`：一个假的邮件工具，按本协议报"新邮件""可疑邮件"、出方案、执行、撤销，数据全是虚构的。`python3 -m luoke_agent.fake_tool --socket <路径>` 起它，对着它看 agent；工具也可以拿它的答复和自己的比。

## 11. 场景样例（2026-11-04 起，先从 luoke-scan 做）

agent 要用某个工具的示例数据时（窗口的截图、测试、演示），从那个工具录的**场景样例**取，不自己手写。样例就是两边之间的接口说明：工具在几种用户处境下，对 agent 发的每个请求真实答了什么。

- **工具那边**：仓库里放 `fixtures/agent/<场景>/`，一个请求一个文件 `{"request", "reply"}`；`manifest.json` 是配件清单，`scenario.json` 写处境、怎么录的、每一步（`steps`：时钟、做了什么、对应哪个文件）。在假数据上起真的服务、时钟固定，照 agent 的请求一条条问，录下答复；编号、路径换成固定写法，README 写明。工具自己的测试里重录一遍和仓库里的比，改了 agent 看到的东西、样例没跟着重录，测试就不过。luoke-scan 的是第一份，格式照它（它的 `fixtures/agent/README.md`）。
- **agent 这边**：`scripts/sync-tool-fixtures.sh <工具> <仓库> [提交]` 把已提交的样例拷进 `fixtures/<工具>/`，记下提交号（`fixtures/<工具>.VERSION`），不改它们。`luoke_agent/replay_tool.py` 照样例回话，真核心连上它，就和连着那个工具、在那种处境下一样：
  - `scripts/window_samples.py` 把窗口这时会拿到的（`/feed` 先给的、`/apps`、每一页、`/permissions`）存成 `window/Sources/LuokeWindow/Resources/samples/<工具>/<场景>.json`，窗口「接上核心」的截图和测试用它；
  - `tests/test_tool_fixtures.py` 查三样：核心问的工具都录过答复；在核心交给窗口的卡片和页上点样例里录的那几下，核心发给工具的和录下的一样（不看 JSON-RPC 的 id 和 clientInfo 的版本）；窗口的示例跟得上样例。
- **对不上时**：先看是哪边变了。工具改了答复：工具的 PR 里说清 agent 要不要跟着改，合了以后 agent 这边重新拷、重新生成。核心改了请求：agent 的 PR 里说清，工具那边重录。一时改不了的写进测试的 `KNOWN`，写明原因、告诉对方；对上了测试会提醒删掉。
- 邮件助手（2026-11-06 起）也录了：`morning`（8 封可疑邮件、一份 8 封要处理的方案）、`tidy-only`、`no-account`，窗口截图里邮件助手的部分从它来。
- 别的工具（螺壳搜索、记忆……）出了样例，照同样的路子接；接上以前，它们在窗口里的示例还是手写的。
