# 螺壳.app 和 agent 核心之间的接口（草案，2026-11-03）

主窗口第一版（[主窗口.md](主窗口.md)）定了以后，窗口、顶部菜单、菜单栏图标由螺壳.app 画，agent 核心供内容。这份写两边怎么接：螺壳.app 怎么起核心，核心的 `agent.sock` 上有哪些接口，窗口上每一块从哪来。

- 现在的界面协议（`luoke_agent/ui.py`，DESIGN §1）是这份的底子：已有的接口不改，只加。
- 窗口的代码是本仓库的 `window/`（`LuokeWindow`），螺壳.app 引它；接口的 Swift 客户端也放在 `window/`，螺壳.app 不用自己写。
- 核心和工具之间照旧是 [工具协议.md](工具协议.md)。窗口不直接连工具，到工具的调用都经 agent（协议 §1b）。
- 会改动东西的调用只来自用户的点按（DESIGN 底线 2）：下面凡是会让工具做事的接口，螺壳.app 只在用户点了以后才调。

状态：草案，要和 luoke-core 商定。标了「第二步」的不进 beta 2。

## 1. 谁出什么

| 窗口上的 | 谁出 | 螺壳.app 怎么拿 |
|---|---|---|
| 侧栏的应用列表、名字、图标；添加应用；装、升级、换回、卸载 | 主控 | 自己（`GET /accessories`、发布清单） |
| 侧栏底部的状态灯和模型名、「设置 · 模型」 | 主控 | 自己 |
| 「今天」：急事横幅、要你决定、已经替你做了、顺便看看里工具报的 | agent | `GET /feed`（§3） |
| 「今天 · 顺便看看」里的「有新版本」 | 主控 | 自己画一行 |
| 活动 | agent | `GET /activity`（§5） |
| 应用的页：概览、基础页、「打开完整界面」 | 工具，经 agent | `GET /apps`、`GET /apps/<id>/pages/<页>`、`POST /open`（§6） |
| 搜索结果 | 工具，经 agent | `POST /search`（§7） |
| 问螺壳、对话（第二步） | agent，模型走主控 | `POST /ask`（§8） |
| 「设置 · 提醒」 | agent | `GET`、`POST /settings`（§9） |
| 「设置 · 权限」 | 应用的经 agent；螺壳自己的由螺壳.app 报给 agent | `GET`、`POST /permissions`，`POST /host`（§10） |
| 「设置 · 隐私」 | 主控；记忆的入口打开螺壳记忆 | 自己 |
| 菜单栏图标的急事和小点、暂停提醒 | agent | `/feed` 的 `cards`、`/settings` 的 `paused_until` |
| 系统通知 | agent 定发不发、发什么；螺壳.app 发 | `/feed` 的 `notify` 事件 |

## 2. 起核心

- 螺壳.app 起核心当子进程，和现在「螺壳 agent.app」的壳一样（`app/Sources/Luoke/Core.swift`）：
  - 用主控带的 Python：`python3 -B -E -s -m luoke_agent serve --home ~/.luoke/agent --memory <记忆库> --hub <主控 socket> --parent-pid <螺壳.app 的 pid>`。
  - 工作目录是核心的代码目录，建议放在 `螺壳.app/Contents/Resources/agent/`，随螺壳.app 一起签名。
  - 核心只往标准错误写元数据。
  - 退出码 75 是核心见主控的 Python 换了版本，马上重起；别的退出隔一会儿再起，间隔逐次加长。
- 关掉「主动提醒」不停核心：窗口和「今天」照旧要它，只是 agent 不发简报和通知（§9 的 `proactive`）。
- 同一个 `--home` 只能有一个核心：核心起来时锁住 `<home>/run/lock`，拿不到就退出，退出码 3（已加：在打开状态库、接管 socket 之前）。并进螺壳的那一版起，主控不再装「螺壳 agent.app」，见到旧的就卸掉（luoke-core 定怎么卸）。
- 核心起好了：`<home>/run/agent.sock` 连得上，`GET /status` 答了。
- `agent.sock` 只认起核心的那个进程：accept 以后取对端的进程号（macOS 用 `LOCAL_PEERPID`），要等于 `--parent-pid`（没给就是父进程），而且它还是核心的父进程；别的进程一律答 403，什么都不做。螺壳.app 要在自己的进程里连（`AgentConnection`）。
- 开发时 `serve --dev`：认本账户的任何进程（命令行的 `feed`、`tap`、`presence`、`window`，`luoke-window-demo --agent`），`--tool` 也只在这时认。`--dev` 只写在命令行上，不看环境变量；正式版不给。agent 自己的开发版壳（不是本机试用的那份）给。

## 3. 「今天」：`GET /feed`

SSE。连上先给现在的全部卡片，再给变化。已有的事件照旧：

| 事件 | 内容 |
|---|---|
| `a2ui` | 一条 A2UI 消息；`surfaceId` 是 agent 的编号（`<来源>/<来源自己的编号>`） |
| `feed` | 现在的整体状态（下面加字段） |
| `notify` | 螺壳.app 去发一条系统通知：`{id, title, body, urgent, silent, …}` |
| `busy` | 某张卡片在处理（按钮先灰掉） |
| `result` | 点按的结果一句话：`{surfaceId, text, error}`，窗口画成底部的提示 |

`feed` 加这些字段（只加；已有的 `order`、`open`、`notices` 不变）：

```jsonc
{
  "order": ["luoke-mail/sus-1", "luoke-mail/new-1", "memory/ask-7", "luoke-scan/clean-3"],
  "open": 3,
  "notices": ["邮件助手现在没在运行。"],
  "cards": [
    {"id": "luoke-mail/sus-1", "app": "luoke-mail", "kind": "suspicious", "section": "urgent",
     "title": "可疑邮件：冒充招商银行", "time": "2026-11-03T09:41:00+08:00"},
    {"id": "luoke-scan/clean-3", "app": "luoke-scan", "kind": "auto-done", "section": "done",
     "title": "清掉了 2.1 GB 缓存", "time": "2026-11-03T08:30:00+08:00"}
  ],
  "brief": {"next": "2026-11-04T08:00:00+08:00"},
  "paused_until": null
}
```

- `cards` 和 `order` 同一个顺序，每张卡片一项。`app` 是来源（工具的配件标识；记忆是 `memory`），窗口拿它找图标和名字。
- `section` 说这张卡片放在「今天」的哪一段：
  - `urgent`：急事横幅；
  - `decide`：要你决定；要权限的（`needs-access`）不管急不急都在这里；
  - `done`：已经替你做了，包括点完还留着、带撤销的，和工具自己做了的（协议 §8a）；
  - `later`：顺便看看，即不急的。
- `title` 是纯文本，给菜单栏图标的急事列表、横幅收起时、画不了卡片时用。`time` 是事项报来的时间；`done` 的是做完的时间。
- `host_ask`（有才带，2026-11-06）：`{"permission": "fda", "button": "b3"}`。这张 `needs-access` 卡片要的是螺壳名下的系统权限，`button` 是要权限的那个按钮：工具的主按钮，没写主按钮时是唯一的工具按钮，认不出来就不带。窗口接着本体时，点这个按钮调 `WindowHost.askPermission`，不发 `/action`（§10）；卡片上别的按钮照 §4。
- 「今天」的灰字计数 = `urgent` 加 `decide` 的张数；菜单栏图标有 `urgent` 的才多一个小点。Dock 不带数字。
- `brief.next` 是下一份简报大约什么时候（只在设置里显示一句，不倒数）。早于现在的，是这一时段还没发、等用户回到 Mac 前；「只在我打开时」和关了主动提醒时是 `null`。`paused_until` 见 §9。

加两个事件：

| 事件 | 什么时候 | 窗口做什么 |
|---|---|---|
| `settings` | 设置改了（别的客户端、或 agent 自己改了，例如「以后少说」） | 换成新的设置（形状同 `GET /settings`） |
| `apps` | 某个应用的运行状态、概览、页列表、权限状态变了：`{"app": "luoke-scan"}` | 重新取 `GET /apps`；正看着这个应用的页就重新取那一页 |

点了通知：螺壳.app 打开窗口到「今天」，照旧报 `POST /window`。

## 4. 点按：`POST /action`

照旧：`{"surfaceId", "sourceComponentId", "context"}`，答 `{"text", "error"}`。基础页（§6）、搜索结果的按钮之外，窗口上所有卡片的按钮都走这里，急事横幅上的按钮也是（横幅就是那张卡片收起来的样子）。

## 5. 活动：`GET /activity`

`GET /activity?before=<ISO 时间>&app=<配件标识>&limit=50`，从新到旧；`before`、`app` 可以不带。

```json
{"rows": [
  {"id": "luoke-mail/new-1", "app": "luoke-mail", "kind": "new-mail", "time": "2026-11-03T09:05:00+08:00",
   "text": "归档 7 封，加了 2 个标签", "outcome": "done", "undo": "luoke-mail/new-1"}
 ],
 "more": true}
```

- 每件答了、放下了、过期了、撤回了的事项一行；工具自己做了的（§8a）也是一行。`outcome`：`done`、`dismissed`、`expired`、`withdrawn`、`auto`。
- `text` 是结果那一句（点按后工具回的，或 §8a 报的标题），纯文本。
- `undo` 是还能撤销时那张卡片的编号，窗口照 §4 点它上面的撤销；不能撤销了就没有这个字段。
- 只存在本机的状态库里（DESIGN 底线 3）；日志照旧只记元数据。要加：状态库存每件的结果那一句。

## 6. 应用的页

页上要螺壳名下系统权限的按钮：工具在按钮的 `context` 里写 `permission`，`GET /apps/<id>/pages/<页>` 的答复多一个 `host_ask`（形状同 §3）。窗口接着本体时，点这个按钮交给本体，不发 `/action`。

按钮的活要这项权限时，工具写 `needs`，答复里的 `host_ask` 多一个 `"then": true`。窗口先交给本体（`askPermission(app:id:ready:)`）：缺什么本体接着要，都有了窗口才发 `/action`，用户没给就不发。窗口没接本体时直接发 `/action`。

`GET /apps`：agent 连着的每个工具一项。名字、图标、版本不在这里，螺壳.app 从主控拿。

```json
{"apps": [
  {"id": "luoke-scan", "running": true,
   "summary": {"count": 3, "text": "3 项等你决定"},
   "pages": [{"id": "overview", "title": "概览"}, {"id": "cleaned", "title": "清理记录"}],
   "ui": null,
   "needs": ["fda"]}
]}
```

- `summary`、`pages`、`ui` 照工具清单的 `service`（协议 §1a），工具没写就是 `null` 或空。`needs` 是这个应用要了、还没给的权限 id。
  - `ui` 只有清单写了 `service.ui.open` 才有，只给 `pages`（工具的动作名不交给窗口）。
  - `summary` 是 agent 每次读 outbox 时一起读的；工具没在运行、读不到是 `null`。
  - `needs`（2026-11-03 实现时定）：「要了」是工具的 outbox 里现在有带这个 `permission` 的 `needs-access`（协议 §1a「用到才要」），「还没给」是状态不是 `granted`（在螺壳名下的照 §10 的 `/host`）；只算 `system`、`account` 两种。清单里登记了、工具还没要的不算。
- `GET /apps/<id>/pages/<页 id>`：答 `{"messages": [...]}`，一组 A2UI 消息，`surfaceId` 是 `<id>/page/<页 id>`；agent 读工具的 `page/<页 id>` 资源，校验和上限同卡片。页上的按钮照 §4 走 `POST /action`。窗口打开这一页时取，`apps` 事件说这个应用变了、或页上点完按钮时再取。
  - 没有这个应用、这一页不在 `service.pages` 里：答 404 `{"error"}`；工具没在运行：答 503 `{"error": "…现在没在运行。"}`。
  - 读不到、不是 JSON、超过 1 MB、校验不过（同卡片：组件不在目录里、超过 200 个、文字超过 2000 字……）：照样答 200，换成一页纯文本（页的标题和「这一页画不了。」），不带工具的内容。
  - 页上点了按钮：agent 转给工具时 `ai.luoke/user-action` 的 `surfaceId` 是页 id（工具自己起的那个）。`/feed` 照卡片发 `busy`、`result`（`replaced: false`）；工具答复里的卡片不画，窗口重新取这一页；概览或权限状态因此变了，再发 `apps`。
- `POST /open`：`{"app": "luoke-mail", "page": "accounts"}`，用户点了「打开完整界面」或深页。agent 调工具的 `service.ui.open`（只读，`where: mac`），由工具自己打开窗口。`page` 可以不带，不带就打开首页。
  - 答 `{"text", "error"}`，同 §4。没有这个应用、工具没写 `service.ui`、`page` 不在 `service.ui.pages` 里：`error: true`，不调工具；`app` 不是字符串答 400。

## 7. 搜索：`POST /search`

**这一版（2026-11-05）**：窗口底部的搜索框只做搜索，不问螺壳。`{"query": "租房合同", "limit": 10}`，答一次 JSON，不是下面的 SSE：

```json
{"results": [{"app": "luoke-search", "name": "螺壳搜索", "messages": [...]}], "failed": ["邮件助手"], "text": "还没有能搜的应用。"}
```

- agent 把词直接给每个登记了 `service.ask.search` 的工具，不经模型；一个工具 10 秒没答算 `failed`。`query` 不超过 200 字，`limit` 是 1 到 50，默认 10，不合要求答 400。
- `messages` 是工具答复里的 A2UI 卡片，校验同基础页，surfaceId 是 `<应用>/search`；按钮走 §4 的 `POST /action`，一个应用只留最近一次搜索的按钮。
- 没搜到（`hits` 是空的）、只给 `hits` 不给卡片的工具，`results` 里没有它。`text` 只在没有工具能搜时才有。
- 按回车才搜，日志不记搜了什么、命中了什么。

下面是以后的形状（结果按来源分段、边搜边画）：

`{"query": "租房合同", "since": "…", "until": "…", "limit": 20}`，答 SSE。agent 对每个登记了 `service.ask.search` 的工具各问一次（协议 §1b），不经模型。

| 事件 | 内容 |
|---|---|
| `hits` | 一个工具答了：`{"search": "<这次搜索的编号>", "app": "luoke-search", "hits": [...]}`，`hits` 的形状同协议 §1b |
| `timeout` | 一个工具 10 秒没答：`{"app": "…"}` |
| `error` | 一个工具没在运行或出错：`{"app": "…"}` |
| `done` | 都答完了（或超时了） |

- 各来源先回先画，不等齐；窗口照协议 §1b 分段，顶上「最相关」放各来源 `strong` 的前两条。
- 打字时窗口自己防抖（停 0.3 秒再搜）；新的搜索开始，窗口断开旧的连接，agent 就不等旧的了。
- 点结果上的按钮：`POST /hit {"search", "app", "hit": "<结果的 id>", "action": "<动作名>"}`。agent 只认这次搜索里这条结果给过的动作和参数，参数由 agent 从结果里取，不从窗口来。答复同 `POST /action`。
- 缩略图：`GET /thumb?app=<配件标识>&ref=thumb/<id>`，答图片本身（`image/jpeg` 或 `image/png`）；不是 JPEG、PNG，超过 256 KB，或长边超过 2048，就答 404，窗口画占位框。agent 和窗口都不写磁盘缓存。
- 日志不记搜了什么、命中了什么。

## 8. 问螺壳：`POST /ask`（第二步）

`{"text": "押金是多少", "context": {"page": "luoke-mail", "selection": {…}}}`，答 SSE：`text`（回答的一段字，接着前面的）、`card`（一张 A2UI 卡片，`surfaceId` 是 `ask/<编号>`）、`done`。

- 模型经主控的任务 `luoke-agent.chat` 用（DESIGN §6）；模型只能做取数据的只读调用，要改动东西的回成卡片，让用户点。
- `context.selection` 是窗口里选中的东西，当数据，放进提示词里标明「以下是数据」的块。
- 钉到今天：`POST /ask/pin {"id": "ask/<编号>"}`，这张卡片进「今天 · 要你决定」，答了就和别的卡片一样。
- 展开成对话：同一个接口，`context` 带 `"thread": "<编号>"`；对话记录存在本机，在「活动」里列出来。
- 一问一答不留痕迹：不钉、不展开的，窗口收起就丢。

## 9. 设置：`GET /settings`、`POST /settings`

`GET` 答全部；`POST` 只带要改的那几项，答改完的全部，并推一个 `settings` 事件。认不得的项、值不对答 400，什么都不改。

```jsonc
{
  "proactive": true,                              // 主动提醒
  "brief": "morning",                             // morning 每天早上 / twice 早晚各一次 / on_open 只在我打开时
  "quiet": {"start": "22:00", "end": "08:00"},    // 免打扰；null 是不设
  "paused_until": null,                           // 暂停提醒到什么时候（菜单栏图标的「暂停提醒一小时」）
  "kinds": [                                      // 每类事怎么说；只读的列表，改用 modes
    {"id": "luoke-mail:suspicious", "app": "luoke-mail", "label": "可疑邮件", "mode": "now", "default": "now"},
    {"id": "memory:ask", "app": "memory", "label": "记忆想问的", "mode": "brief", "default": "brief"}
  ],
  "modes": {"luoke-mail:new-mail": "brief"}       // 改过的：now 当场说 / brief 放进简报 / window 只放在窗口里 / off 不要
}
```

- 简报按时刻发（替掉现在的「攒满一小时」`brief_minutes`）：
  - 「每天早上」：免打扰结束后，用户第一次在 Mac 前时发；
  - 「早晚各一次」：早上同上，晚上是 18:00 以后第一次在 Mac 前；
  - 「只在我打开时」：不发通知，打开窗口时「今天」排好。
  - 不在 Mac 前就等回来；上一份没打开，下一份不响、只更新。
- `paused_until`：到点以前不发简报和通知（急事也不发，菜单栏图标照旧有小点）；窗口照旧更新。菜单栏图标写「暂停到 HH:MM」。
- 关掉 `proactive`：不发简报和通知，菜单栏图标不再有小点；「今天」照旧。

## 10. 权限：`GET /permissions`、`POST /permissions`、`POST /host`

`GET /permissions`：每个应用的 `permissions`（协议 §1a）一行，状态照工具的 `permissions` 资源；`owner: "luoke"` 的那几项状态照螺壳.app 报的（下面）。

```json
{"rows": [
  {"app": "luoke-scan", "id": "fda", "kind": "system", "owner": "luoke", "tcc": "SystemPolicyAllFiles",
   "title": "完全磁盘访问", "facts": ["看文件名、大小、修改时间", "结果不出这台 Mac"], "without": "degrade",
   "state": "denied", "can": ["settings"]},
  {"app": "luoke-scan", "id": "auto", "kind": "delegate", "title": "不用点就清 4 类", "state": "on", "can": ["off"]}
]}
```

- `can` 是这一行现在能做的：`request`（不在螺壳.app 里的工具，有系统弹窗的，工具自己发起）、`settings`（没有弹窗的，打开系统设置对应那一页；在螺壳名下的见下）、`on`、`off`（代你做的事）、`open`（账号去工具自己的界面）、`remove`（移除账号）。`each-time` 的只列出来，没有 `can`。
- 每行的字段（2026-11-03 实现时定）：`app`、`id`、`kind`、`title`、`state`，有才带的 `owner`、`tcc`、`facts`、`without`，除了 `each-time` 都有 `can`。`state` 是 `granted` / `denied` / `ask` / `on` / `off`，不知道是 `null`（工具没在运行、读不到、螺壳.app 还没报）。清单里工具的动作名（`request`、`on`、`remove`）和 `page` 不交给窗口。`GET` 时 agent 先问一遍各工具现在的 `permissions`（协议 §1a：不缓存成"已授权"）。
- `can` 怎么定：

  | `kind` | `can` |
  |---|---|
  | `system` | 清单写了 `request`、状态是 `ask`、不在螺壳名下：`request`（工具要在运行）；否则 `tcc` 键登记过就 `settings`（给了的也能去系统设置收回） |
  | `delegate` | 清单写了 `on`、工具在运行：开着给 `off`，关着给 `on`；不知道状态就是空的 |
  | `account` | 工具在运行：写了 `service.ui.open` 给 `open`；写了 `remove`、状态是 `granted` 给 `remove` |
  | `each-time` | 没有 `can` |

- `POST /permissions {"app", "id", "op"}`，`op` 是 `can` 里的一个，只在用户点了以后调。`request`、`on`、`off`、`remove` 调工具的写入动作（带 `ai.luoke/user-action`）；`open` 调 `service.ui.open`；`settings` 答复里带系统设置那一页的地址（`url`），由窗口在螺壳.app 里打开，核心不自己开（luoke-core#68 定）。答 `{"text", "error"}`，`settings` 另带 `url`。
  - agent 先照工具现在报的状态再算一遍 `can`；`op` 不在里面答 `{"text": "这一项现在不能这样改。", "error": true}`，不转给工具。工具没在运行时，除了 `settings` 都答「…现在没在运行。」。没有这个应用、这一项权限也是 `error: true`；缺字段、`op` 不是上面六个之一答 400。
  - 调工具时（2026-11-03 实现时定，协议 §1a 进 main 时补进去）：`request`、`remove` 参数 `{}`；`on`、`off` 都调清单的 `on` 动作，参数 `{"on": true}` / `{"on": false}`；这几样不管工具标没标只读，都带 `ai.luoke/user-action`，`surfaceId` 是 `permissions`、`componentId` 是权限 id。`open` 参数 `{"page": "<清单的 page>"}`（在 `service.ui.pages` 里才带）。做完再读一遍工具的 `permissions`，变了发 `apps`。
  - `settings`：系统设置的地址只从 agent 自己的对照表来（`luoke_agent/apps.py` 的 `SETTINGS_PANES`：完全磁盘访问、文件与文件夹、辅助功能、录屏、输入监控、自动化、日历、提醒事项、通讯录、照片、摄像头、麦克风），不认工具给的网址；没登记的 `tcc` 键没有 `settings`。窗口只打开 `x-apple.systempreferences:` 开头的地址（`AgentConnection.settingsOpener`）。
- 权限页上 `owner: "luoke"` 的列在螺壳名下，下面写哪些应用在用。清单没写 `owner` 的照工具自己报的状态。
- 系统权限是螺壳的（`owner: "luoke"`，2026-11-06）：问用户的窗口由本体画，问 macOS 的也是本体，工具不再自己问。
  - 权限页上这一行的 `request`、扳开「允许」开关，和 `needs-access` 卡片上 `host_ask` 的按钮，窗口调 `WindowHost.askPermission(app:id:)`，不发 `POST /permissions`、`/action`。这一行的 `settings`：系统还没问过（系统设置里还没有这一项）调 `WindowHost.askSystem(id:)`，只问系统；确认过又被拒绝调 `askPermission`，本体直接打开系统设置，不出窗口。其他时候（已经授权、没确认过又被拒绝）只是打开系统设置，照常走 `POST /permissions`。本体开自己的窗口，用户答应了再问 macOS；结果照下面的 `POST /host` 报，卡片因此撤下。
  - 窗口没接本体时（`luoke-window-demo`、开发版的壳）照旧走 `POST /permissions`、`/action`。不在螺壳名下的行照旧：`request` 只给不在螺壳.app 里的工具。
  - 每个应用一个开关「允许」，在螺壳那一行下面：用户同意了才放行，`WindowModel.hostConfirmed`（键是 `<应用>#<权限 id>`，值是确认的时间）里有的是开。扳关调 `WindowHost.setPermission(app:id:on:)`；扳开先出本体的窗口，用户在窗口里确认才开；确认记录由本体存，启动时和变了时经 `reportHostPermissions(_:confirmed:)` 给窗口。本体没报时（`hostConfirmed` 是 nil）开关算开。
  - 没放行只是用户和螺壳的约定：螺壳不让这个应用用这一项。系统授权给的是螺壳，系统不替螺壳拦，界面上写「没放行：你确认了它才能用这一项」，不说系统挡住了它。用户关掉以后再用到时，工具报 `needs-access`，卡片留着，用户点了才问（授权框只紧跟用户的操作）。
- `POST /host {"permissions": {"fda": "granted"}, "confirmed": {"luoke-scan": {"fda": "2026-11-06T07:00:00Z"}}}`：螺壳.app 报它自己的权限状态和用户确认过哪些，启动时报一次，变了再报（例如用户从系统设置回来）。agent 据此决定 `needs-access` 的卡片还留不留：螺壳已经有了、这个应用也确认过，就撤掉。`confirmed` 整份替换，没报时只看状态。
  - 照下面这个形状（luoke-core#68 定）；这项授权归螺壳自己、状态由螺壳.app 报，顶层 ADR 0021 已经定了。
  - 现在的写法（2026-11-03）：键是权限 id，和工具清单里 `owner: "luoke"` 那一项的 `id` 对上（例如 `fda`）；值是 `granted` / `denied` / `ask`，`null` 是不再报这一项；只改报了的几项，别的照旧。不对答 400，什么都不改；对了答 `{}`。只存在内存里，核心重启后等螺壳.app 再报。
  - 报了 `granted`、这个应用确认过：工具为在螺壳名下的那一项报的 `needs-access` 撤掉（算撤回），工具还列着也不画；后来不再是这样，下次读 outbox 时回来。用到这一项的应用都发 `apps`。

## 15. 本体给核心的通道：由本体起的工具（2026-11-05，草案，等和 luoke-core 商定）

工具协议 §2a 的工具（`transport: "stdio"`，先是螺壳扫描的 Go 版）由本体起，连接由本体交给核心。

- **通道**：本体起核心时，用一对 Unix socketpair 的一端当核心的标准输入，参数加 `--host-stdin`。没有文件路径，只有本体和它起的这个核心拿得到，不用对端核对。核心退出、重起时本体另建一对。
- **要连接**：核心写一行 `{"id": N, "open": "<配件>"}`。同一时间核心只有一个在等回复。
- **本体核对**：这个配件是螺壳带着的（`Contents/Helpers`）、用户开着、程序签名标识对。然后：
  - 新建一对 socketpair，一端当标准输入输出起工具（螺壳扫描：`luoke-scan mcp --this-mac`，命令、环境、提权的描述符见扫描仓库的 `docs/host-interface.md`）；
  - 另一端用 SCM_RIGHTS 随回复 `{"id": N, "ok": true}` 交给核心；
  - 给不了就回 `{"id": N, "error": "<一句原因>"}`，不带描述符。
- **本体那一份留到工具退出再关**：交出去马上关的话，macOS 可能把还在路上的 socket 当没人要的收掉，核心拿到的就是断的（11-05 测过：马上关时 960 次里断 14 次，留着 3840 次一次没断）。核心写完请求就关掉写的一头，工具照样读得到结尾。
- **本体收尾**：工具退出时回收；超过它的上限（扫描 300 秒）没退出就结束它。同时开着的连接要设上限。
- **核心那边**：`luoke_agent/hostlink.py`；10 秒内本体没答就当这一次没在运行；本体那头断了，之后的都当没在运行。
